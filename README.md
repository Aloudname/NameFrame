## 前言

旧的框架并不好用。使用过程中发现其接口过于开放非常难用、组件间通信方式乱、初始化和管理方法完全暴露不好控制等等。这已经不是一般的问题了，必须要出重拳！艰难地品尝自己烹饪的东西后，决定回锅重炒，根据上一版应用过程中的问题，结合一些毕设过程中的实践心得，提出底层的设计思想，在此基础上重新开发。这次，我一定要成功口牙！嘻嘻！♪(^∇^*)

## 开发日志

### 2026.7.23

根据一些毕设过程中的实验实践心得，结合第一版的问题，提出一些设计思想。**一定要将框架开发设计大思想进行到底！**

| # | 设计思想 | 具体 |
|---|------|--------|
| 1 | 灵活拆/封，高度定制 | 框架不限制自由度 |
| 2 | CLI 是唯一入口 | `nfm` 命令做操作 |
| 3 | 数据管线标准化 | 预处理行为与数据格式无关 |
| 4 | 约定优于配置，配置优于代码 | 渐进、定制的配置 |
| 5 | 渐进式复杂度 | 简单的任务简单做，复杂的任务才复杂 |
| 6 | 层层封装 + 穿透 API | 默认透明，需要时可深入任意层 |
| 7 | 依赖注入 | 没有隐式的全局状态 |
| 8 | 配置的运行时锁 | 配置冻结，运行时不可写入 |
| 9 | 接口隔离 | 最小接口，通过数据对象通信 |
| 10 | 模块可组合 | 组件自由组合，配置声明即可 |
| 11 | 方便注册 | 三种最简单的注册方法 |
| 12 | 配置是模块的唯一接口 | 每个模块显式声明可配置项 |
| 13 | 算子多后端派发 | 装饰器派发，自动回退 |
| 14 | 数据流零拷贝 | 同设备数据传递引用 |
| 15 | 分布式训练透明化 | 通过配置文件管理分布式 |
| 16 | 状态即数据 | 所有状态可序列化 |
| 17 | 确定性复现 | 自动管理种子 |
| 18 | 实验分隔 | 实验自动记录数据集指纹 |
| 19 | 环境可移植 | 环境签名，可跨机器复现 |
| 20 | 尽早失败，验证前置 | 训练前的多方检查 |
| 21 | 资源调度 | 显存估算，OOM 预警 |
| 22 | 测试友好 | 组件可隔离测试，自动生成假数据 |
| 23 | 日志指标管理 | JSON 日志、指标面板、内置可视化 |
| 24 | 可配置可视化 | 结果图表由配置驱动 |
| 25 | 多实验管理与对比 | 实验自动归档，可比 |
| 26 | 训练推理统一 | 训练推理共用预处理 |
| 27 | 内置超参搜索 | 配置声明搜索空间，框架编排搜索 |
| 28 | 插件先于分支 | 轻量化核心，插件方便扩展 |
| 29 | PyTorch 优先 | 不做其余框架兼容 |
